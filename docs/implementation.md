# Обзор реализации AivibeBoard

Документ описывает фронтенд-скелет **AivibeBoard** — SaaS-интерфейс управления проектами в духе Trello / Jira / Linear / Notion с акцентом на AI-блоки. Реализован **только клиент**: без бэкенда, базы данных, внешней авторизации и настоящих AI-запросов. Вход и регистрация работают в браузере и не обращаются к серверу.

---

## Цель и границы

- **Сделано:** полноценный каркас приложения, рабочий дашборд, заглушки остальных разделов с реальными UI-взаимодействиями на мок-данных, страница входа и регистрации, защита маршрутов.
- **Не сделано:** API, серверная авторизация, хеширование паролей, Telegram, почта, настоящие модели AI. Остальные данные приложения (задачи, документы, настройки) по-прежнему живут только в памяти до обновления страницы.

Сессия и аккаунты, созданные через регистрацию, сохраняются в `localStorage` и переживают перезагрузку. Пароли зарегистрированных пользователей лежат там в открытом виде — это демо, не схема для продакшена. Кнопки и формы, которые выглядят рабочими, выполняют действие в рамках демо.

## Маршруты

| Путь | Страница |
|------|----------|
| `/auth` | вход и регистрация, без оболочки приложения |
| `/` | для авторизованного пользователя редирект на `/dashboard` |
| `/dashboard` | полный дашборд |
| `/tasks` | список задач, фильтры, смена статуса |
| `/projects` | карточки проектов |
| `/team` | участники workspace |
| `/knowledge-base` | документы, поиск, «загрузка» файлов |
| `/ai` | AI-ассистент и блок генератора |
| `/ai#generator` | якорь «Генератор задач» (пункт в сайдбаре) |
| `/integrations` | карточка Telegram |
| `/settings` | профиль и демо-настройки |

Все маршруты кроме `/auth` обёрнуты в `RequireAuth`. Без сессии любой адрес, включая несуществующий, ведёт на `/auth`. Обратный переход запоминается: после входа открывается страница, с которой пользователя перенаправили, иначе `/dashboard`. Если сессия уже есть, `/auth` сразу возвращает в приложение (`GuestOnly`).

## Структура кода

```
src/
  app/           App, router
  components/    layout (Sidebar, Header, Search), auth (RequireAuth, GuestOnly), ui-kit
  data/          mockUsers, mockTasks, mockProjects, …
  features/      dashboard, tasks, projects, ai-assistant, …
  hooks/         useWorkspaceData, useMediaQuery, useOnOutside
  pages/         страницы по маршрутам, в том числе Auth
  store/         useAppStore, useAuthStore (Zustand)
  types/         доменные типы и константы статусов
  utils/         format, ai (шаблоны), tones, guards, auth
```

Импорты локальных модулей — с расширением `.ts` / `.tsx` (требование `verbatimModuleSyntax`).

## UI и layout

- Оболочка: `h-svh`, боковая панель ~250px, на экранах `< lg` — выезжающее меню и оверлей.
- Визуальный стиль: светлый SaaS, zinc/white, акцент indigo/violet, AI-блоки на violet-фоне.
- **Header:** хлебные крошки, поиск по проектам/задачам, «Новая задача», уведомления, аватар.
- **Sidebar:** переключатель workspace (Aivibe / Студия Northwind), навигация, профиль, кнопка «Выйти».
- **Вход:** отдельный экран по центру, вкладки «Вход» и «Регистрация», те же zinc/indigo-стили, что у остального интерфейса. Оболочка с сайдбаром на этой странице не показывается.

## Состояние (Zustand)

Store `useAppStore` хранит:

- задачи, проекты, активность, документы, историю AI;
- текущего пользователя: пустая строка, пока нет сессии; после входа — id мок-пользователя или зарегистрированного аккаунта;
- активный workspace;
- флаги: sidebar, модалка создания задачи, Telegram по workspace;
- настройки: компактные списки, дайджест, алерты (переключатели без реальной отправки).

Мутации добавляют записи в ленту активности с русскими сообщениями в кавычках «ёлочками».

Отдельный store `useAuthStore` отвечает за вход, регистрацию и выход. При старте `useAppStore` читает `localStorage`:

| Ключ | Содержимое |
|------|------------|
| `aivibe-auth-session` | `{ userId }` текущей сессии |
| `aivibe-registered-accounts` | аккаунты, созданные на вкладке «Регистрация»: почта, пароль и объект пользователя |

Зарегистрированные пользователи подмешиваются к `mockUsers`. Если сохранённый `userId` больше никому не принадлежит, сессия сбрасывается. `setCurrentUserId` и `addUser` в `useAppStore` связывают сессию со списком участников workspace.

## Ключевые взаимодействия

1. **Создание задачи** — модалка, добавление в store, запись в активность.
2. **Смена статуса** — select в списке задач; при «Готово» — тип события `completed`.
3. **Поиск** — проекты и задачи текущего workspace, Enter переходит к первому результату.
4. **AI** — `src/utils/ai.ts`: regex по русским и английским ключевым словам (маркетинг, сайт, бот, дизайн, данные…), до 5 подзадач; история до 12 записей на workspace.
5. **Knowledge base** — drag-and-drop / выбор файла, документ появляется в списке сессии.
6. **Telegram** — переключатель «Подключить / Отключить» без реального API.
7. **Settings** — компактные списки влияют на отступы в TaskList; тема зафиксирована светлой с пояснением.
8. **Вход** — почта и пароль. Для участников из моков (например `alex@aivibe.io`) принимается любой пароль от 6 символов. Для аккаунта с регистрации пароль должен совпасть.
9. **Регистрация** — имя, почта, пароль и повтор пароля. Почта должна быть уникальной и похожей на адрес. Новый пользователь получает роль «Участник», инициалы из имени и доступ к активному workspace, затем сразу входит в приложение.
10. **Выход** — кнопка в сайдбаре очищает сессию и возвращает на `/auth`.

## Локализация

По запросу весь пользовательский текст переведён на **русский**: навигация, дашборд («Добрый день, Алексей»), вход и регистрация, формы, уведомления, мок-активность, AI-шаблоны, `aria-label`, `index.html` (`lang="ru"`).

Бренды **Aivibe**, **AivibeBoard**, **Medialog**, **Northwind** в названиях проектов сохранены где уместно.
