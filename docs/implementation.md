# Обзор реализации AivibeBoard

Документ описывает фронтенд **AivibeBoard** — SaaS-интерфейс управления проектами в духе Trello / Jira / Linear / Notion с акцентом на AI-блоки. Проекты, команда, база знаний и AI работают на мок-данных в памяти браузера. Вход, регистрация, роль участника и доски с задачами подключены к **Supabase**: почта и пароль проверяются на сервере, сессия хранится клиентом Supabase, роль и задачи доски записываются в базу.

---

## Цель и границы

- **Сделано:** каркас приложения, рабочий дашборд, разделы на мок-данных, вход и регистрация через Supabase Auth, выбор роли IT-команды, доски и их задачи в Supabase, защита маршрутов.
- **Не сделано:** API для проектов и документов, Telegram, почтовые рассылки приложения, настоящие модели AI. Эти данные по-прежнему живут только в памяти до обновления страницы.

Сессия Supabase переживает перезагрузку. Пароли в `localStorage` не сохраняются. Кнопки вне входа, которые выглядят рабочими, выполняют действие в рамках демо.

## Маршруты

| Путь | Страница |
|------|----------|
| `/auth` | вход и регистрация, без оболочки приложения |
| `/` | для авторизованного пользователя редирект на `/dashboard` |
| `/dashboard` | полный дашборд |
| `/boards` | список досок текущего пользователя |
| `/boards/:boardId` | колонки задач выбранной доски |
| `/tasks` | редирект на `/boards` |
| `/projects` | карточки проектов |
| `/team` | участники workspace |
| `/knowledge-base` | документы, поиск, «загрузка» файлов |
| `/ai` | AI-ассистент и блок генератора |
| `/ai#generator` | якорь «Генератор задач» (пункт в сайдбаре) |
| `/integrations` | карточка Telegram |
| `/settings` | профиль, выбор роли и демо-настройки |

Все маршруты кроме `/auth` обёрнуты в `RequireAuth`. Без сессии любой адрес, включая несуществующий, ведёт на `/auth`. Обратный переход запоминается: после входа открывается страница, с которой пользователя перенаправили, иначе `/dashboard`. Если сессия уже есть, `/auth` сразу возвращает в приложение (`GuestOnly`).

## Состояние (Zustand)

Store `useAppStore` хранит:

- задачи, проекты, активность, документы, историю AI;
- текущего пользователя: пустая строка, пока нет сессии; после входа — id пользователя Supabase;
- активный workspace;
- флаги: sidebar, модалка создания задачи, Telegram по workspace;
- настройки: компактные списки, дайджест, алерты (переключатели без реальной отправки).

Мутации добавляют записи в ленту активности с русскими сообщениями в кавычках «ёлочками».

Отдельный store `useAuthStore` отвечает за вход, регистрацию и выход:

- вход — `supabase.auth.signInWithPassword`;
- регистрация — `supabase.auth.signUp`, имя и ключ роли уходят в `user_metadata`;
- смена роли — `supabase.auth.updateUser` и строка `profiles`;
- выход — `supabase.auth.signOut`;
- при старте `App` один раз вызывает `init`: `getSession()` и `onAuthStateChange`.

Пока статус сессии `loading`, `RequireAuth` и `GuestOnly` показывают «Загрузка…» и не перенаправляют. Иначе обновление главной на миг открывало бы форму входа.

Пользователь Supabase превращается в тип `User`: id из Auth, имя из metadata (если его нет — часть почты до `@`), роль из `user_metadata.role`, инициалы и цвет. Если ключ роли неизвестен, в интерфейсе остаётся «Участник». Пользователь добавляется в список `users`, иначе сайдбар и `useWorkspaceData` не найдут текущего человека. Мок-участники команды остаются в интерфейсе.

Клиент создаётся в `src/lib/supabase.ts` из переменных окружения. Образец имён — `.env.example`, рабочие значения — в `.env.local` (файл не коммитится, Vite читает его только при старте `npm run dev`):

| Переменная | Откуда взять |
|------------|----------------|
| `VITE_SUPABASE_URL` | Project Settings → Data API → Project URL |
| `VITE_SUPABASE_ANON_KEY` | Project Settings → API Keys, publishable-ключ `default` или legacy anon |

В проекте Supabase для немедленного входа после регистрации выключите **Authentication → Sign In / Providers → Email → Confirm email**. Если подтверждение включено, `signUp` не возвращает сессию: форма просит перейти по ссылке из письма, а главная откроется уже после входа. Адреса на `@example.com` Supabase отклоняет. При лимите писем форма показывает «Слишком много попыток подряд».

### Роль

При регистрации роль обязательна. Тот же список есть в настройках: выбор сразу сохраняется. Ключи и подписи живут в `src/data/teamRoles.ts`.

| Ключ | Подпись |
|------|---------|
| `frontend` | Фронтенд-разработчик |
| `backend` | Бэкенд-разработчик |
| `fullstack` | Фулстек-разработчик |
| `mobile` | Мобильный разработчик |
| `qa` | QA-инженер |
| `devops` | DevOps-инженер |
| `design` | UI/UX-дизайнер |
| `product` | Менеджер продукта |
| `project` | Менеджер проектов |
| `lead` | Тимлид |
| `analyst` | Аналитик |

Роль пишется в два места: `user_metadata.role` и колонка `profiles.role`. Триггер `handle_new_user` при создании пользователя копирует имя и роль из metadata в `profiles`. В настройках сначала обновляется строка профиля, затем metadata. Если второй шаг не удался, в `profiles` возвращается прежняя роль. Подпись в сайдбаре и на карточке профиля берётся из metadata. У досок роль участника читается из `profiles.role`. Пустая роль и неизвестный ключ показываются как «Участник».

### Доски и задачи

Доски, участники досок и задачи лежат в Supabase (`boards`, `board_members`, `tasks`). Создание, правка, смена статуса и удаление задачи доски уходят в `public.tasks`. На время запроса кнопки модалки заблокированы. Если запись не удалась, локальное состояние откатывается, а на доске или в модалке показывается ошибка. Проекты и задачи дашборда по-прежнему мок-данные и в эту таблицу не пишутся.

## Ключевые взаимодействия

1. **Создание задачи** — модалка, добавление в store, запись в активность.
2. **Смена статуса** — select в списке задач; при «Готово» — тип события `completed`.
3. **Поиск** — проекты и задачи текущего workspace, Enter переходит к первому результату.
4. **AI** — `src/utils/ai.ts`: regex по русским и английским ключевым словам (маркетинг, сайт, бот, дизайн, данные…), до 5 подзадач; история до 12 записей на workspace.
5. **Knowledge base** — drag-and-drop / выбор файла, документ появляется в списке сессии.
6. **Telegram** — переключатель «Подключить / Отключить» без реального API.
7. **Вход** — почта и пароль уходят в Supabase. Пустые поля, пароль короче 6 символов, неверная пара и неподтверждённая почта показываются на форме по-русски. Успех открывает страницу, с которой пришли, иначе `/dashboard`.
8. **Регистрация** — имя, роль, почта, пароль и повтор пароля. Роль выбирается из списка IT-команды, без неё форму не отправить. Почта должна быть уникальной. При включённом подтверждении почты сессии сразу нет, но роль уже лежит в metadata и в `profiles`. Когда Supabase возвращает сессию, пользователь сразу попадает в приложение: в сайдбаре видны имя и роль с формы.
9. **Настройки** — тот же список ролей. Смена сразу пишется в Supabase и обновляет подпись в сайдбаре. Компактные списки влияют на отступы в TaskList; тема зафиксирована светлой с пояснением.
10. **Задачи доски** — создание, редактирование, перенос между колонками и удаление сохраняются в Supabase. Ошибка записи остаётся на экране, карточка не пропадает из прежнего места.
11. **Выход** — кнопка в сайдбаре вызывает `signOut` и возвращает на `/auth`.

## Как проверить вход

Приложение должно быть запущено, а в `.env.local` — URL и ключ того проекта Supabase, к которому подключён клиент. Чтобы регистрация сразу открывала главную, выключите **Confirm email** (путь выше).

1. Откройте `/auth` без сессии. Если вы уже внутри, нажмите **Выйти**.
2. Вкладка **Регистрация**: имя, роль, новая почта, пароль от 6 символов и тот же пароль ещё раз. Без роли форма не отправляется. После создания аккаунта в сайдбаре видны имя и выбранная роль.
3. Откройте **Настройки** и смените роль. Подпись на карточке и в сайдбаре меняется сразу. В Supabase в `profiles.role` и в metadata пользователя лежит один и тот же ключ.
4. **Выйти**, затем вкладка **Вход** с той же почтой и паролем. Роль, выбранная в настройках, сохраняется.
5. Обновите главную. Сессия сохраняется, форма входа не мигает.
6. Неверный пароль и повторная регистрация той же почты оставляют на форме с текстом ошибки. Разные пароли в двух полях дают «Пароли не совпадают».
7. В Supabase откройте **Authentication → Users** и таблицу `profiles`: пользователь создан, роль заполнена.
8. Выйдите и откройте `/boards` напрямую. Откроется `/auth`, после входа — снова список досок.
9. На доске создайте задачу, перенесите её в другую колонку и обновите страницу. Задача остаётся в новой колонке.
