# Обзор реализации AivibeBoard

Документ описывает фронтенд **AivibeBoard** — SaaS-интерфейс управления проектами в духе Trello / Jira / Linear / Notion с акцентом на AI-блоки. Задачи, проекты и остальные разделы работают на мок-данных в памяти браузера. Вход и регистрация подключены к **Supabase Auth**: почта и пароль проверяются на сервере, сессия хранится клиентом Supabase.

---

## Цель и границы

- **Сделано:** каркас приложения, рабочий дашборд, заглушки остальных разделов с UI на мок-данных, страница входа и регистрации через Supabase Auth, защита маршрутов.
- **Не сделано:** API для задач и документов, Telegram, почтовые рассылки приложения, настоящие модели AI. Эти данные по-прежнему живут только в памяти до обновления страницы.

Сессия Supabase переживает перезагрузку. Пароли в `localStorage` не сохраняются. Кнопки вне входа, которые выглядят рабочими, выполняют действие в рамках демо.

## Маршруты

| Путь | Страница |
|------|----------|
| `/auth` | вход и регистрация, без оболочки приложения |
| `/` | для авторизованного пользователя редирект на `/dashboard` |
| `/dashboard` | полный дашборд |
| `/tasks` | список задач, фильтры, смена статуса |
| `/projects` | карточки проектов |
| `/team` | участники workspace |
| `/knowledge-base` | документы, поиск, «загрузка» файлов |
| `/ai` | AI-ассистент и блок генератора |
| `/ai#generator` | якорь «Генератор задач» (пункт в сайдбаре) |
| `/integrations` | карточка Telegram |
| `/settings` | профиль и демо-настройки |

Все маршруты кроме `/auth` обёрнуты в `RequireAuth`. Без сессии любой адрес, включая несуществующий, ведёт на `/auth`. Обратный переход запоминается: после входа открывается страница, с которой пользователя перенаправили, иначе `/dashboard`. Если сессия уже есть, `/auth` сразу возвращает в приложение (`GuestOnly`).

## Состояние (Zustand)

Store `useAppStore` хранит:

- задачи, проекты, активность, документы, историю AI;
- текущего пользователя: пустая строка, пока нет сессии; после входа — id пользователя Supabase;
- активный workspace;
- флаги: sidebar, модалка создания задачи, Telegram по workspace;
- настройки: компактные списки, дайджест, алерты (переключатели без реальной отправки).

Мутации добавляют записи в ленту активности с русскими сообщениями в кавычках «ёлочками».

Отдельный store `useAuthStore` отвечает за вход, регистрацию и выход:

- вход — `supabase.auth.signInWithPassword`;
- регистрация — `supabase.auth.signUp`, имя уходит в `user_metadata.name`;
- выход — `supabase.auth.signOut`;
- при старте `App` один раз вызывает `init`: `getSession()` и `onAuthStateChange`.

Пока статус сессии `loading`, `RequireAuth` и `GuestOnly` показывают «Загрузка…» и не перенаправляют. Иначе обновление главной на миг открывало бы форму входа.

Пользователь Supabase превращается в тип `User`: id из Auth, имя из metadata (если его нет — часть почты до `@`), роль «Участник», инициалы и цвет. Он добавляется в список `users`, иначе сайдбар и `useWorkspaceData` не найдут текущего человека. Мок-участники команды остаются в интерфейсе.

Клиент создаётся в `src/lib/supabase.ts` из переменных окружения. Образец имён — `.env.example`, рабочие значения — в `.env.local` (файл не коммитится, Vite читает его только при старте `npm run dev`):

| Переменная | Откуда взять |
|------------|----------------|
| `VITE_SUPABASE_URL` | Project Settings → Data API → Project URL |
| `VITE_SUPABASE_ANON_KEY` | Project Settings → API Keys, publishable-ключ `default` или legacy anon |

В проекте Supabase для немедленного входа после регистрации выключите **Authentication → Sign In / Providers → Email → Confirm email**. Если подтверждение включено, `signUp` не возвращает сессию: форма просит перейти по ссылке из письма, а главная откроется уже после входа. Адреса на `@example.com` Supabase отклоняет. При лимите писем форма показывает «Слишком много попыток подряд».

## Ключевые взаимодействия

1. **Создание задачи** — модалка, добавление в store, запись в активность.
2. **Смена статуса** — select в списке задач; при «Готово» — тип события `completed`.
3. **Поиск** — проекты и задачи текущего workspace, Enter переходит к первому результату.
4. **AI** — `src/utils/ai.ts`: regex по русским и английским ключевым словам (маркетинг, сайт, бот, дизайн, данные…), до 5 подзадач; история до 12 записей на workspace.
5. **Knowledge base** — drag-and-drop / выбор файла, документ появляется в списке сессии.
6. **Telegram** — переключатель «Подключить / Отключить» без реального API.
7. **Settings** — компактные списки влияют на отступы в TaskList; тема зафиксирована светлой с пояснением.
8. **Вход** — почта и пароль уходят в Supabase. Пустые поля, пароль короче 6 символов, неверная пара и неподтверждённая почта показываются на форме по-русски. Успех открывает страницу, с которой пришли, иначе `/dashboard`.
9. **Регистрация** — имя, почта, пароль и повтор пароля. Почта должна быть уникальной. При включённом подтверждении почты сессии сразу нет. Когда Supabase возвращает сессию, пользователь сразу попадает в приложение, в сайдбаре видно имя с формы.
10. **Выход** — кнопка в сайдбаре вызывает `signOut` и возвращает на `/auth`.

## Как проверить вход

Приложение должно быть запущено, а в `.env.local` — URL и ключ того проекта Supabase, к которому подключён клиент. Чтобы регистрация сразу открывала главную, выключите **Confirm email** (путь выше).

1. Откройте `/auth` без сессии. Если вы уже внутри, нажмите **Выйти**.
2. Вкладка **Регистрация**: имя, новая почта, пароль от 6 символов и тот же пароль ещё раз. Адрес становится `/dashboard`, в сайдбаре — имя с формы.
3. **Выйти**, затем вкладка **Вход** с той же почтой и паролем. Снова открывается `/dashboard`.
4. Обновите главную. Сессия сохраняется, форма входа не мигает.
5. Неверный пароль и повторная регистрация той же почты оставляют на форме с текстом ошибки. Разные пароли в двух полях дают «Пароли не совпадают».
6. В Supabase откройте **Authentication → Users** и убедитесь, что пользователь создан.
7. Выйдите и откройте `/tasks` напрямую. Откроется `/auth`, после входа — снова `/tasks`.
